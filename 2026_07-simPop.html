Data

The example uses eusilc13puf. Despite the “puf” in the name this is not a public-use file of real microdata – the help page is titled “Synthetic EU-SILC 2013 survey data” and states it was itself synthetically generated from the real Austrian EU-SILC 2013 sample provided by Statistics Austria. 13 513 persons in 5 977 households, 62 of the original survey’s variables simulated.

Two consequences worth stating out loud rather than discovering later:

  • We are generating synthetic data from synthetic data. Everything below is a valid demonstration of the method, but no real person is involved – which matters most for the inference attack at the end.
  • The help page claims the sample weights “do not reflect the true population sizes of Austria and its regions”. That is boilerplate shared with the other example datasets and it is not true of the weight we actually use (see below).

Eleven variables are kept: the household identifier and size, region, the three demographics, economic status, citizenship, personal and household gross income, and the sampling weight.

A trap in that last one. The column literally named weight in eusilc13puf is all 1s – it is there for the “treat this file as if it were already a population” case. The weight this document uses is column 46, rb050, the official EU-SILC personal cross-sectional weight, which is then renamed to weight. And rb050 is a real weight: it sums to 8 332 260, i.e. 98% of Austria’s 2013 population, and its regional totals match the actual federal states.

It has been flattened, though: only 9 distinct values, one per region. Real EU-SILC weights are calibrated per household to age and sex margins as well. Here every person in a region carries the same weight, so what we have are regional design weights and nothing more.

df$eco_stat <- factor(df$eco_stat)

# what makes ~24% of the target variable exactly 0 -- which matters later when

df$pgrossIncome[is.na(df$pgrossIncome)] <- 0

# shrinks the generated population to ~83k persons purely to keep the runtime of
# this demo bearable, and it means every absolute count from here on is 100x too
# small. Multiply by 100 to read them, or drop this line for a real run.
df$weight <- df$weight / 100

Define structure

The household structure of the synthetic population is created by extrapolating the sample using the sample weights/calibrated weights and re-sampling (alias sampling) when method = “distribution” (if one does not wish to create a population, one should use sample weights = 1 as a variable in one’s data). For this process, the household structure must contain a set of user-defined “basicHHvars”. In this case, we use age, sex, and region. Other methods may be selected, such as “direct,” which employs the Horvitz-Thompson estimator to estimate the population totals for each combination of stratum and household size. Alternatively, “multinom” may be utilized to estimate the conditional probabilities within the strata using a multinomial log-linear model and random draws from the resulting distribution.

All values accepted by method in simStructure():

method what it does
"distribution" used here. Alias sampling: estimates how many households of each size belong in each stratum, then resamples that many whole households from the sample.
"direct" Horvitz-Thompson estimation of the population totals for every stratum × household-size combination.
"multinom" Multinomial log-linear model for the conditional probabilities within strata, followed by random draws. 
simPop <-
  simStructure(
    data = inp,
    method = "distribution", # direct
    basicHHvars = c("age", "sex", "region"),
    seed = SEED
  )

Define categorical variables

Categorical variables are simulated using the defined household structure and the weights as an input. The package offers two methodological approaches to add/simulate the categorical variables: one is a model-based simulation, the other a synthetic reconstruction. In this example, we utilize the model-based simulation. A multinomial model is fit to sample data, so that the categorical variable to be simulated is the response variable and the other defined household variables serve as predictors. Subsequently, the model employs the conditional probabilities to “predict” the manifestation of the selected variable. In our example, we generate categorical variable economic status and citizenship.

In addition to the “multinom” argument method, which entails the estimation of conditional probabilities using multinomial log-linear models and random draws from the resulting distributions, several other methods are accepted.

All values accepted by method in simCategorical():

method model note
"multinom" multinomial log-linear model used here. The AMELI approach; additive, so it sees no interactions unless you write them into regModel.
"distribution" none The odd one out: no model at all, just random draws from the observed conditional distributions of the multivariate realisations. This is the synthetic reconstruction approach from the introduction, sitting inside the same function.
"ctree" single conditional-inference tree (partykit) Finds interactions on its own. Cheap, and a good sanity check against "multinom".
"cforest" forest of conditional-inference trees (partykit)
"ranger" random forest (ranger) Much faster than "cforest" on large populations.
"xgboost" gradient boosting (xgboost)

All of these are ready to use – partykit, ranger and xgboost are hard dependencies of simPop, not optional extras, so nothing needs installing.

Switching method is a one-word edit, which makes this a good place to stop and try one: "ctree" on the same two variables takes seconds and its results can be compared against the multinomial fit using exactly the utility measures further down.

simPop <-
  simCategorical(
    simPop,
    additional = c("eco_stat", "citizenship"),
    method = "multinom",
    seed = SEED
  )

Define continuous variables

It is recommended that continuous variables be defined after categorical variables, as the continuous variables are added to the structure using a modeling approach. This approach allows for the simulated categorical variables to be accounted for when simulating the continuous ones. There are several approaches to simulate continuous variables in simPop. The default approach is based on the same methodology as the simulation of the categorical variables, described above. The continuous variable is categorized (using quantiles as the default) and the multinomial model is estimated. In the final step, random draws are taken from the intervals of the categories into which the predictions at the population level fall. An alternative approach is the “lm” method, which is based on a two-step regression model with random error terms. This method involves first fitting a logistic regression model and then a linear regression model. This is necessary when considering semi-continuous distributions, as otherwise only the linear regression imputation is applied. The other methods are Poisson for count variables and xgboost.

All values accepted by method in simContinuous():

method model note
"multinom" multinomial log-linear model on a categorised version of the variable The package default. The variable is cut into categories (quantiles unless breaks/probs say otherwise), the category is predicted, then a value is drawn at random from inside it. Tail behaviour is controlled by gpd, threshold and upper.
"lm" two-step regression with random error terms First a logistic regression for “is it zero or not”, then a linear regression for the amount. The two steps are what makes it suitable for semi-continuous variables such as income, where a large share of the values are exactly zero. With zeros = FALSE only the linear part runs.
"poisson" Poisson regression For count variables.
"xgboost" gradient boosting

Note that the choice interacts with the shape of the variable rather than being free. Personal gross income is 24% zeros, so "lm" with zeros = TRUE is the natural fit; household gross income has no such spike and is handled below with "multinom". Both calls appear in this document precisely so the two can be compared.

In this example, we will simulate the personal gross income, a semi-continuous variable, using the “lm” method with the two-step regression and the household income with the “multinom” method, a multinomial model.

# nr_cpus = 1 turns off simPop's parallelisation. Counter-intuitively this makes
# the whole document about twice as fast -- this step alone drops from roughly
# 20 seconds to under one, because at this data size the cost of starting and
# feeding the workers dwarfs the work itself. Worth knowing before running it
# in front of an audience.
#
# Note how thin the model is: personal income is explained by sex and household
# size only. The richer specification is commented out on the next line. This
# keeps the demo fast, but it is also the reason the income distribution is
# reproduced far less convincingly than the categorical variables were -- worth
# coming back to when we measure utility below.
simPop <- simContinuous(
  simPop,
  method = "lm",
  additional = "pgrossIncome",
  regModel = ~ sex + hsize, #+ eco_stat + citizenship + age,
  zeros = TRUE,
  log = FALSE,
  #const = 1,
  alpha = NULL, #0.05,
  residuals = TRUE,
  seed = SEED,   # without this, simContinuous() does not seed at all
  nr_cpus = 1
)
simPop <- simContinuous(
  simPop,
  method = "multinom",
  additional = "hgrossIncome",
  regModel = ~ sex + hsize + eco_stat + citizenship + pgrossIncome + I(pgrossIncome^2),
  # With parallelisation off this becomes the slowest step of the document,
  # around 8 seconds -- still half of what the two steps cost together before.
  upper = 200000,
  equidist = FALSE,
  nr_cpus = 1,
  seed = SEED
)

Post-calibration of the synthetic population

Although the sample used as input for the simulation of the synthetic population had been calibrated to known marginals, the resulting population will not exactly match these marginals due to the randomness in the data generation process. If a (quasi) perfect match to the known marginals is a requirement the function calibPop() can be applied. It uses simulated annealing – the combinatorial-optimization approach – to swap households between groups until the known margins are matched, so it is a post-processing step on an already generated population, not an alternative way of generating one. It is not run here: it takes considerably longer than everything above put together.

Propensity Scores

The measures above compare one distribution at a time. A propensity score judges the whole dataset at once, by turning “are these two datasets alike?” into a prediction problem: stack the real sample on top of the synthetic population, label which row came from where, and try to train a model that tells them apart. If a reasonable model cannot separate them, the two are distributionally similar. The density plot is the actual result to look at – two overlapping humps mean the model is guessing.

data_sample$group <- 0   # real sample
data_pop$group    <- 1   # synthetic population

combined_data <- rbind(data_sample , data_pop |> dplyr::select(-hgrossIncomeCat))

res_logreg <- glm(
  group ~ region + hsize + eco_stat  +  sex + citizenship + pgrossIncome + hgrossIncome ,
  data = combined_data,
  family = binomial()
)

Two things have to be said before any number from this is quoted.

The groups are nowhere near equal in size – about 13.5k real records against 83k synthetic ones. A classifier scores well here simply by answering “synthetic” every time, so the reference point cannot be 1/2. It has to be c, the share of synthetic records, which is the propensity every row would receive if the two sources were truly indistinguishable.

pMSE and the Brier score point in opposite directions. pMSE measures distance from c: small means the model cannot tell the sources apart, so small is good. The Brier score measures how well the model predicts actual membership, so small is bad – it means the two sources separate cleanly. Confusing the two inverts the conclusion, which is why both are printed here with their direction spelled out.

c_ref <- mean(combined_data$group)   # share of synthetic records

# pMSE (cf. Woo et al. 2009): squared distance of each propensity from the value
# expected under "no difference between the datasets". SMALL = GOOD utility.
pmse <- mean((combined_data$propensity_score_log_reg - c_ref)^2)

# Brier score: accuracy of predicting actual membership. SMALL = BAD utility,
# because it means the model separates real from synthetic.
brier <- mean((combined_data$propensity_score_log_reg - combined_data$group)^2)

# A model that learned nothing and always answers c scores exactly c(1-c).
# That is the number the Brier score above has to be read against: anything
# close to it means the covariates carry no usable signal about which dataset a
# row came from.
brier_trivial <- c_ref * (1 - c_ref)

data.frame(
  measure   = c("c (share of synthetic records)",
                "pMSE  -- distance from c",
                "Brier -- accuracy of group prediction",
                "Brier of a trivial 'always guess c' model"),
  value     = round(c(c_ref, pmse, brier, brier_trivial), 5),
  direction = c("--", "smaller is better", "smaller is worse", "reference")
)
##                                     measure   value         direction
## 1            c (share of synthetic records) 0.86032                --
## 2                  pMSE  -- distance from c 0.00015 smaller is better
## 3     Brier -- accuracy of group prediction 0.12005  smaller is worse
## 4 Brier of a trivial 'always guess c' model 0.12017         reference

Snoke et al. (2018) standardise pMSE by its variance under the null, which turns it into a scale-free ratio and allows an actual significance test. That is the right thing to do if the number is going to be reported rather than merely looked at; here the density plot carries the message.

A cleaner alternative to worrying about c at all is to draw a random subsample of the synthetic population the same size as the real sample. Then c is 1/2 by construction, the textbook formula applies unchanged, and the density plot becomes easier to read.

Confidentiality (inference attack)

Scenario. The intruder has complete information on region, household size, age, gender, economic status and citizenship of a person – the key variables – and wants to learn that person’s personal gross income, the confidential variable. Only the synthetic population has been published; the real sample has not.

The attack is to fit a model for income on the published synthetic data, then apply it to the key variables the intruder already holds, and see how close the prediction lands to the truth.

Note what this does and does not measure. It is an attribute-disclosure test: how much can be inferred about a known person’s income. It is not re-identification – no records are matched one-to-one and no threshold for a “successful” match is applied anywhere below. Re-identification would be a different exercise, and on fully synthetic data a considerably more awkward one, because a synthetic record does not correspond to any single real person to begin with.

Predict confidential variable (personal gross income) in the synthetic data

# Define intruder knowledge
intruder_knowledge <- data_sample |> select(-hhid, -pgrossIncome, -hgrossIncome, -weight)
# Write out the true values of income
true_pgrossincome <- data_sample |> select(pgrossIncome, pid)
# Fit a model on the synthetic population for the personal gross income
inf_attack_model <- lm(pgrossIncome ~ sex + hsize + eco_stat + citizenship + age + region, data = data_pop)

Compare the true values to the predicted

intruder_knowledge$predictions = predict(inf_attack_model, newdata = intruder_knowledge)
compare_df<- left_join(intruder_knowledge, true_pgrossincome, by = "pid")
compare_df$result <- abs(compare_df$pgrossIncome - compare_df$predictions)
mean(compare_df$result)
## [1] 23108

Is that error large or small?

On its own the number above says nothing at all. It is a mean absolute error in euros, and whether it constitutes a privacy failure depends entirely on what it is compared against. Two reference points settle it:

  • A trivial guess. An intruder who never saw the data and simply always answers “the median income” already achieves some error. If the attack does not clearly beat that, it has extracted essentially nothing.
  • The ceiling. The same model fitted on the real sample is what an intruder holding the true microdata could manage. The attack cannot do better than this, and the gap between the two is exactly what the synthesis destroyed.
y <- compare_df$pgrossIncome
mae <- function(pred) mean(abs(y - pred))

ceiling_model <- lm(pgrossIncome ~ sex + hsize + eco_stat + citizenship + age + region,
                    data = data_sample)

data.frame(
  scenario = c("attack: model fitted on the synthetic population",
               "ceiling: same model fitted on the real sample",
               "baseline: always guess the median",
               "baseline: always guess the mean"),
  MAE = round(c(mae(compare_df$predictions),
                mae(predict(ceiling_model, newdata = data_sample)),
                mae(median(y)),
                mae(mean(y))))
)
##                                           scenario   MAE
## 1 attack: model fitted on the synthetic population 23108
## 2    ceiling: same model fitted on the real sample 19584
## 3                baseline: always guess the median 23716
## 4                  baseline: always guess the mean 24723

The attack lands only marginally better than always guessing the median, and well short of the ceiling. Both halves matter: the first says the published population leaks very little about any individual’s income, the second says the reason is the synthesis itself rather than the income simply being unpredictable.

One caveat against over-claiming from this. The income model in simContinuous() above used only sex and hsize, so income was weakly tied to the key variables in the synthetic data from the start. Part of the privacy protection on display here is therefore a side effect of a deliberately thin model – the same thin model that cost us utility earlier. Utility and disclosure risk are being traded against each other, and this document sits at one particular point on that curve rather than demonstrating a free lunch.
